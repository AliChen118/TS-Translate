## 一、快速上手

标准使用流程：

1. **配置** —— 填写翻译接口凭据（阿里云 / 腾讯云 / 百度 / 有道智云 / AI 大模型**五选一**，推荐可直连的**阿里云**或 **AI 接口**），点「测试连接」验证。
2. **术语库** —— 导入 Excel（`.xlsx`）术语对照表，保证专业术语翻译一致。
3. **规则库** —— 配置**特殊词条**（如字体名强制译成 Arial）与**正则规则**（标签、占位符、符号数字等不翻译）。**内置 13 条默认正则规则，开箱即用。**
4. **翻译** —— 日常文本翻译，自动应用术语库与规则库并高亮命中。
5. **TS 翻译** —— Qt Linguist `.ts` 语言文件的翻译（一次可导入多个 `.ts` 或整个文件夹）。

顶部统计卡实时显示四项本机统计：**翻译次数、TS 处理次数、当天已翻译字符数、当月已翻译字符数**（只统计真正送进翻译接口的原文字符，按本机时区的自然日 / 自然月累计，鼠标悬停卡片可看口径说明）。

> 推荐顺序：**先配好术语库与规则库，再做 TS 翻译** —— 两者都会直接影响 `.ts` 的翻译质量。

## 二、接口配置

配置页提供**五种**翻译接口供应商，任选其一。**阿里云与 AI 接口支持浏览器直连、无需任何代理**；百度、有道、腾讯云因接口不返回 CORS 头，必须配置「代理地址前缀」才能使用。

切换供应商时，界面按如下顺序重排字段：① 凭据（恒为第一行两列）② 供应商特有的附加项（如腾讯云的地域、AI 的模型与地址）③ 代理地址前缀。**「代理地址前缀」只在必须代理的供应商下显示**，可直连的供应商直接隐藏该项；AI 供应商还会额外显示「翻译提示词」。

接口地址方面：**阿里云与腾讯云的接口地址已内置，无需填写**；百度、有道、AI 接口仍可自定义地址。云接口签名（阿里云 HMAC-SHA1、腾讯云 TC3-HMAC-SHA256）全部由本工具在浏览器端自动计算。

| 供应商 | `value` | 是否可直连 | 需要填写 |
| --- | --- | --- | --- |
| 阿里云翻译（**默认**） | `aliyun` | ✅ | AccessKey ID / AccessKey Secret |
| 腾讯云翻译 | `tencent` | ❌ 需代理 | SecretId / SecretKey / 地域 Region |
| 百度翻译开放平台 | `baidu` | ❌ 需代理 | APP ID / 密钥 / 服务地址 |
| 有道智云翻译 | `youdao` | ❌ 需代理 | 应用ID(appKey) / 密钥(appSecret) / 服务地址 |
| AI 大模型翻译 | `ai` | ✅ | API Key / 模型名称 / 服务地址（+ 可选提示词） |

### 剩余免费额度

配置页供应商选择框下方会显示当前接口的**剩余免费额度**：进度条 + 已用 / 总额度 / 剩余字符数。

- **计量方式**：本机统计 —— 每成功调用一次接口，按**送出的字符数**累加；**每月自动清零**已用额度，也可点「清零已用」手动归零。
- **总额度**：预置各平台公开免费额度（阿里云 100 万、腾讯云 500 万、百度 / 有道 100 万字符；AI 无统一免费额度），**仅作参考**；请以平台控制台实际数值为准，直接改输入框即可保存。
- **为什么不是平台实时查询**：百度 / 有道 / 腾讯云必须走代理，且各家大多**没有开放的额度查询接口**，浏览器拿不到真实剩余额度；AI 接口按 token 计费、无统一免费额度，因此只统计本机已送出字符数、不显示剩余。
- 进度条 ≥80% 变橙、用尽变红，可用作提前提醒，**实际扣费以平台账单为准**。

### 阿里云翻译（默认，支持直连）

- 登录阿里云控制台 → **AccessKey 管理**（`ram.console.aliyun.com/manage/ak`）创建 AccessKey，建议使用 RAM 子账号并仅授予 `alimt` 翻译权限。
- 到**机器翻译控制台**（`mt.console.aliyun.com`）开通「通用版机器翻译」服务。
- 在配置页填入 **AccessKey ID** 与 **AccessKey Secret** 即可，接口地址无需填写。
- 签名算法为阿里云 RPC 签名 V2（HMAC-SHA1），由本工具自动计算；接口单次上限 5000 字符，工具按 **4500 字符**分片后按序请求并拼接；QPS 50，**接口请求间隔**建议填 `100～200`。
- ✅ `mt.aliyuncs.com` 返回 `Access-Control-Allow-Origin: *`，**浏览器直连即可使用，无需代理**。

### 腾讯云翻译

- 登录腾讯云控制台 → **API 密钥管理**（`console.cloud.tencent.com/cam/capi`）获取 **SecretId** 与 **SecretKey**（建议使用子账号密钥）。
- 到**机器翻译控制台**（`console.cloud.tencent.com/mt`）开通机器翻译（TMT）服务。
- 在配置页填入 SecretId / SecretKey，并按需修改**地域（Region）**，默认 `ap-guangzhou`；接口地址无需填写。
- 签名算法为 TC3-HMAC-SHA256，由本工具自动计算；接口单次上限约 2000 字符，工具按 **1900 字符**分片。
- ⚠️ `tmt.tencentcloudapi.com` **不返回任何 CORS 头，浏览器直连 100% 失败**，需先填「代理地址前缀」；**只想免代理直连的话，直接选阿里云或 AI 接口即可**。

### 百度翻译开放平台

- 打开 `fanyi-api.baidu.com` → 注册并实名认证。
- 选择「通用翻译」产品，建议开通**高级版**（标准版仅 1 次/秒，高级版 10 次/秒，免费额度更大）。
- 在「开发者信息」页复制 **APP ID** 与**密钥**，填入配置页并保存。
- 签名算法为 `MD5(appid+q+salt+key)`，由本工具自动计算；长文本按 **2000 字符**分片、按序请求后拼接。
- 批量机翻（TS 翻译）的节奏由**接口请求间隔**控制：标准版填 `1000`，高级版可填 `100～200`。
- ⚠️ **百度接口不返回任何 CORS 响应头，浏览器直连 100% 失败**（报 `Failed to fetch` / 网络请求失败）。要用百度，必须先在配置页填好「代理地址前缀」。

### 有道智云翻译

- 打开 `ai.youdao.com` → 注册 → 控制台 → **创建应用**，服务选择「文本翻译」。
- 复制**应用ID（appKey）**与**应用密钥（appSecret）**填入配置页。
- 签名算法为 `SHA-256(appKey+input+salt+curtime+appSecret)`，其中 `input` 按官方规则截取（≤20 字符全量，否则前 10 + 长度 + 后 10），由本工具自动计算；长文本按 **2000 字符**分片。
- ⚠️ **有道接口只返回 `Allow-Methods/Headers`、不返回 `Allow-Origin`，浏览器直连同样 100% 失败**，需先填「代理地址前缀」。

### AI 大模型翻译（OpenAI 兼容）

- 支持任何 OpenAI 兼容的 `/chat/completions` 接口：OpenAI、DeepSeek、通义千问、Kimi、本地 Ollama 等。
- 填写：**接口地址**、**API Key**、**模型名称**（如 `gpt-4o-mini`、`deepseek-chat`、`qwen-plus`）。
- 可自定义**翻译提示词**（System Prompt），占位符 `{{from}}` 与 `{{to}}` 会被替换为语言名称；留空则用内置默认提示词。
- **想省事就用这一档**：DeepSeek（`https://api.deepseek.com/v1/chat/completions`，模型 `deepseek-chat`）、通义千问（`https://dashscope.aliyuncs.com/compatible-mode/v1/chat/completions`，模型 `qwen-plus`）**都支持浏览器直连，无需代理**。
- AI 翻译质量更高、更贴近专业语境，但速度与费用高于传统接口。
- ⚠️ OpenAI 官方 `api.openai.com` 禁止浏览器直连，必须经代理或改用上面两家。

- **语言代码会自动按供应商换算**：界面里「管理语种」的代码统一是小写形态（`zh`、`zh-tw`、`pt-br`…），各家接口写法并不相同，工具在发送前自动转换 —— 百度 `ja→jp`、`ko→kor`、`zh-tw→cht`；阿里云 `ja→ja`、`zh-tw→zh-tw`；腾讯云 `ja→jp`、`ko→kr`、`zh-tw→zh-TW`；有道 `zh→zh-CHS`、`zh-tw→zh-CHT`。未收录的代码会先退化为「取主语言」再试（`pt-br→pt`、`en-US→en`），仍无法匹配才原样发送。所以遇到「语言方向不支持」一般是该供应商本身不支持这门语言，而不是代码写法的问题。

## 三、跨域（CORS）说明

### 为什么会出现这个报错

**同一个 HTML 从浏览器里直接请求翻译接口，能不能成功只看「接口有没有返回 CORS 响应头」，与密钥、账号、余额都无关。**

浏览器出于同源策略，会先检查响应里有没有 `Access-Control-Allow-Origin`；没有就直接丢弃响应，并让 `fetch` 抛 `TypeError: Failed to fetch` —— 你看到的就是这条错误。注意此时**请求其实已经发出去了**（可能已经扣了字符量），只是浏览器不允许页面读取结果。

下表是抓取真实响应头得到的结论（等价于 `curl -H "Origin: null" <接口地址>`）：

| 供应商 | CORS 响应头 | 浏览器能否直连 |
| --- | --- | --- |
| 阿里云翻译 mt.aliyuncs.com | `Allow-Origin: *` | ✅ 可直连 |
| DeepSeek api.deepseek.com | 回显 `Allow-Origin`（含 `null`） | ✅ 可直连 |
| 通义千问 dashscope.aliyuncs.com | `Allow-Origin: *` | ✅ 可直连 |
| 百度翻译 fanyi-api.baidu.com | 无任何 `Access-Control-Allow-*` 头 | ❌ 一定失败，必须代理 |
| 有道智云 openapi.youdao.com | 有 `Allow-Methods` / `Allow-Headers`，但没有 `Allow-Origin` | ❌ 一定失败，必须代理 |
| 腾讯云翻译 tmt.tencentcloudapi.com | 无任何 `Access-Control-Allow-*` 头 | ❌ 一定失败，必须代理 |
| OpenAI 官方 api.openai.com | 禁止浏览器直连 | ❌ 需代理或换服务商 |

结论：**想免代理直连，请选阿里云翻译、DeepSeek、通义千问等支持直连的接口。** 百度、有道、腾讯云的直连在任何浏览器、任何时间都无法成功 —— 这不是版本回退，而是这些服务器根本不返回 CORS 响应头。

> 另外两种「以前能成功」的情况：① 在应用内置浏览器面板里点的（面板环境可能不施加同源策略）；② 浏览器装了 CORS 解禁类扩展。换成普通浏览器双击打开后就会失败。

**如何一眼确认**：点「测试连接」，会先做一次不校验跨域的 `no-cors` 探测 —— 服务器能通却仍报错 = 跨域拦截（服务器没问题）；探测本身也失败 = 网络 / 地址问题（不是 CORS）。诊断结论会直接打印在测试结果框里。

### 解决办法

- **方案 A（推荐）：本地代理。** 把下面任一脚本保存为 `proxy.js` / `proxy.py` 运行，然后在配置页的「代理地址前缀」填入 `http://127.0.0.1:8765/translate?url=` —— 需要代理的供应商（百度 / 有道 / 腾讯云）共用这一个前缀。

Node.js 代理（需本机装有 Node，支持 GET / POST 转发）：

```
// proxy.js   运行: node proxy.js
const http = require("http");
const https = require("https");

http.createServer((req, res) => {
  const cors = {
    "Access-Control-Allow-Origin": "*",
    "Access-Control-Allow-Headers": "*",
    "Access-Control-Allow-Methods": "GET, POST, OPTIONS"
  };
  if (req.method === "OPTIONS") { res.writeHead(204, cors); return res.end(); }

  const m = req.url.match(/^\/translate\?url=(.+)$/);
  if (!m) { res.writeHead(400, cors); return res.end("bad request"); }
  const target = decodeURIComponent(m[1]);
  if (!target.startsWith("https://")) { res.writeHead(403, cors); return res.end("forbidden"); }

  const u = new URL(target);
  const headers = Object.assign({}, req.headers);
  delete headers.host; delete headers.origin; delete headers.referer;
  const up = https.request({ hostname: u.hostname, port: u.port || 443,
    path: u.pathname + u.search, method: req.method, headers }, r => {
    res.writeHead(r.statusCode, Object.assign({
      "Content-Type": r.headers["content-type"] || "application/json; charset=utf-8" }, cors));
    r.pipe(res);
  });
  up.on("error", () => { res.writeHead(502, cors); res.end(); });
  req.pipe(up);
}).listen(8765, () => console.log("proxy on http://127.0.0.1:8765"));
```

Python 代理（需本机装有 Python + flask）：

```
# proxy.py   运行: pip install flask && python proxy.py
from flask import Flask, request, Response
import urllib.request

app = Flask(__name__)

@app.route("/translate", methods=["GET", "POST", "OPTIONS"])
def t():
    cors = {"Access-Control-Allow-Origin": "*",
            "Access-Control-Allow-Headers": "*",
            "Access-Control-Allow-Methods": "GET, POST, OPTIONS"}
    if request.method == "OPTIONS":
        return Response("", status=204, headers=cors)
    url = request.args.get("url", "")
    if not url.startswith("https://"):
        return "forbidden", 403
    data = request.get_data() if request.method == "POST" else None
    rq = urllib.request.Request(url, data=data, method=request.method)
    ct = request.headers.get("Content-Type")
    if ct:
        rq.add_header("Content-Type", ct)
    with urllib.request.urlopen(rq) as r:
        body = r.read()
    return Response(body, content_type="application/json; charset=utf-8", headers=cors)

app.run(port=8765)
```

- **方案 B（最省事）：改用支持直连的接口。** 阿里云翻译（`mt.aliyuncs.com`）与多数 AI 大模型接口（DeepSeek、通义千问等）都支持浏览器直连，**零代理配置**。
- **方案 C：** 将本 HTML 部署在带反向代理的局域网服务器上，由服务器转发请求。

## 四、翻译页

- 选择源 / 目标语言（13 种内置语言，可自行增删），点 ⇄ 可互换；输入文本后点**翻译**或按 `Ctrl+Enter`。
- **规则库与术语库同样生效**：`<b>` 等标签、`%1s` / `{0}` / `${VAR}` 等占位符、符号数字会被**保护起来不送进接口**（`keep`），译文里原样保留；特殊词条直接替换为指定译文（`repl`）；命中术语库的片段**直取术语库译文**（`gloss`），同样不送接口。命中详情在「命中统计」卡片查看。
- 源文下方实时显示**字符数**。

### 命中高亮与统计

翻译结果区与下方「命中统计」卡片会把命中按来源分别着色、逐条计数。**界面图例只展示计入统计的三类来源**；此外还有一类「大小写规则改动的片段」会以蓝色虚线高亮提示，但**按设计不纳入命中统计**（详见下表第 4 行）。

**高亮样式**：翻译页与规则库「规则测试」**共用同一套样式令牌**（底色 + 1px 边框 + 3px 圆角 + 3px 左右内边距），两处形态完全一致 —— 特殊词条 = 规则测试的「特殊词条」，正则规则基准色 = 规则测试的「保护片段」，改一处两处同步。

| 来源类型 | 样式 | 是否计入统计 | 说明 |
|---|---|---|---|
| 术语库词条 | 琥珀底 + 琥珀边框 | 计入 | 命中术语库里的词；原文按「术语」列匹配，译文按目标语言译文列匹配 |
| 规则库特殊词条 | 橙底 + 橙边框（与「规则测试」的「特殊词条」同款） | 计入 | 命中规则库「特殊词条」表的 `src`（原文）/ `dst`（译文） |
| 正则规则匹配项 | 绿色系（基准与「规则测试」的「保护片段」同款），**每条规则一个色阶**（共 6 阶循环），同规则同色、不同规则易分辨 | 计入 | 命中规则库「正则规则」的保护片段 |
| 大小写规则改动的片段 | 蓝色 + 虚线边框（**不在图例中展示**） | **不计入** | 命中所启用的**大小写规则**会改动的字符（如 `Harvester` → `harvester`）；仅作高亮提示 |

### 切片优先级（＝命中重叠优先级）

**翻译前先切片**：待翻译文本按「特殊词条 > 正则规则 > 术语库」逐段匹配切片，优先级高的先命中、先切分。同一位置被多级命中时取权重最高的一级（**不与低优先级比长度**）；同一级内多条命中取最长的一条，等长取先定义者；从左到右扫描、先到先切。切片拼接后**不丢失原文内容与格式**。

| 优先级 | 来源类型 | 权重 | 命中后的处理 | 是否送翻译接口 | 是否做大小写规整 |
|---|---|---|---|---|---|
| 1（最高） | 规则库特殊词条 | 3 | 强制替换为指定内容（`repl`） | 否 | 否 |
| 2 | 正则规则 | 2 | 原样保留（`keep`） | 否 | 否 |
| 3 | 术语库词条 | 1 | 直取术语库译文（`gloss`） | 否 | 由该词条的「大小写规整」决定 |
| 4（最低） | 大小写规则 | 0 | 不切片，只作用于译文 | — | 是 |
| — | 以上均未命中 | — | 送接口翻译（`text`） | 是 | 是 |

- **同级处理**：优先级**相同时取更长的匹配**；长度也相同时取先出现的一条。
- **术语库切片幂等**：只在「前两级没占用」的 `text` 片段上再切一次，切完在数组上打 `glossSliced` 标记，重复调用不会二次切分（TS 规划阶段切一次、翻译阶段再传进来是安全的）。
- **影响范围**：这条优先级同时决定**切片顺序**、结果区高亮颜色、悬浮提示里显示的名称，以及「命中统计」表格中该片段被归到哪一类。
- **权重单点**：四级权重定义在 `ZTW.rules.PRI`（`{ term:3, regex:2, glossary:1, case:0 }`）；`ZTW.highlight` **直接引用同一对象**（`var PRI=ZTW.rules.PRI;`），因此「切片顺序 / 高亮着色 / 统计归类」三条链路同源，改一处三处同步。
- **大小写规则为什么排最后**：它标记的是「会被大小写规则改动的字符」，属于**提示性**信息而非命中来源；排在最后可保证它绝不会遮挡术语库 / 特殊词条 / 正则的真实命中，也不会让统计数字虚高。

### 翻译编排（切片 → 逐段翻译 → 组装）

- 片段类型共四类：`repl`（特殊词条，强制替换）、`keep`（正则保护，原样保留）、`gloss`（术语库，直取译文）、`text`（其余，送接口）。
- **只有 `text` 片段会送进翻译接口**；`repl` / `keep` / `gloss` 一律不调用接口、不消耗配额。
- **大小写规整只作用于两类结果**：术语库译文（按该词条的「规整 / 不规整」逐条判定）与接口返回的译文。`repl` / `keep` 片段**不做任何大小写规整**。
- 术语库词条「不规整」时，其译文用哨兵占位（`\uE000 n \uE001`）在接口返回后原样还原；哨兵只存在于内部字符串，送进接口的原文本不受影响。
- 组装阶段（`assembleParts`）按片段顺序拼接，`keep` 片段带 `spacing` 时补齐词间空格（多余空格收敛为一个、行首不补），保证拼接结果不丢字、格式不乱。

### 高亮与统计的其它口径

- **悬浮提示**：鼠标移到任意高亮片段上，会显示来源名称（如「正则规则：占位符 - 百分号格式化占位符」「大小写规则：翻译结果全部小写」），据此可确定它由哪条术语 / 哪条规则命中。
- **重叠处理**：同一段文字被多条来源命中时，按 **特殊词条 > 正则规则 > 术语库 > 大小写规则** 取优先级最高的一类着色，优先级相同时取更长的匹配，保证不出现样式叠加导致读不清。
- **图例**：结果区下方固定显示色卡图例与优先级说明，由 `ZTW.highlight.legendHTML` 统一产出（禁止各页面手写，避免两处漂移）。
- 匹配规则：术语与特殊词条**默认忽略大小写**（特殊词条沿用规则自身的「忽略大小写」开关），并按**词边界**匹配（`cat` 不会命中 `concatenate`）；中文按子串匹配。正则为用户自定义表达式，非法表达式、零宽匹配、超量命中都会安全跳过。
- **大小写差异不影响统计结果**：当大小写规则生效时，术语 / 特殊词条一律忽略大小写差异，正则规则会额外在「按同一套大小写规则归一化后的文本」上再匹配一轮并按区间去重 —— 所以同一段文字无论大小写怎么变，命中次数都保持一致。

**命中统计表格**

统计卡片按「来源类型 + 词条 / 规则名称」聚合，列为：**来源类型 / 词条或规则名称 / 命中次数**，末尾给出**合计**行（总处数 + 三类各自处数；大小写规则按设计不计入）。

- **搜索**：工具条左侧搜索框可对**词条 / 规则名称**模糊过滤（忽略大小写），输入即筛选。
- **来源类型筛选**：「来源类型」下拉可在**全部来源 / 术语库词条 / 规则库特殊词条 / 正则规则**之间切换，只看某一类命中。
- **按命中次数排序**：点击表头**「命中次数」**循环切换 **默认 → 次数降序(▼) → 次数升序(▲)**；次数相同时按名称稳定排序。
- 三者可叠加使用；处于筛选 / 排序状态时，工具条右侧显示「筛选：n / N 行 · x / X 处」，合计行会标注「（已筛选）」并给出全量处数。
- **分页**：统计表与术语库 / 规则库各列表**共用同一套分页组件**，**每页 10 行**，底部分页条给出「共 N 条 / 第 x / y 页」，支持**上一页 / 下一页**与**输入页码跳转**（越界会自动收敛）；搜索、来源类型筛选、排序任一变化都会回到第 1 页。
- **悬浮看完整提示**：所有搜索框的宽度都会按**提示词长度自适应**（CJK 与拉丁字符分开估算，各页面同一套口径）；个别窄屏下仍被截断时，鼠标悬停即可看到**完整内容**。
- **结果区实时预览**：尚未翻译时，结果区会随输入**实时显示原文的命中高亮**（与下方统计同步）；翻译后显示译文高亮。若在已有译文的情况下继续改原文，结果区保留上一次译文（不会被清掉），统计卡片会提示「结果区仍是上一次译文」。
- **刷新时机**：编辑原文时**自动刷新**（输入停止 0.6 秒后）；翻译完成后自动切换为统计**译文**；切换源语言 / 目标语言、从其他页签切回翻译页时立即重算；也可随时点「刷新统计」手动重算。**切换目标语言**时会一并重算译文态统计，但译文态是按「结果区那份译文实际用的语种」去匹配术语的 —— 若新选的目标语言与它不一致，卡片会提示「当前译文是『英语』的结果，改选『俄语』后请重新点『翻译』」，而不会拿新语种的词表去匹配旧译文（否则命中数会假性塌成 0）。
- 翻译前统计的是**原文**命中，翻译后统计的是**译文**命中，卡片左上角「统计对象」会标明当前统计的是原文还是译文、属于哪个语种。
- **性能防护**：单次扫描有长度上限（2 万字符，超出会在卡片上提示）、候选命中总量上限与时间预算（约 150ms）三重保护，长文本不会卡顿。

## 五、术语库

术语库是「按语言给出各语言对照」的词表，是保证专业术语一致性的核心数据。

### 显示语种

- 表头上方一排语种标签（显示各语种的本地名，悬浮可看中文名 + 英文名），点击可**显示 / 隐藏**对应语言列，随时可再点回来。
- 右侧按钮在**「全选语种 / 全不选语种」之间切换**：当前全部显示时点一下隐藏全部，再点恢复全部；选择自动记住，可以做到一列语言都不显示。

### 管理语种（新增 / 删除语言类别）

点语种标签右侧的「**管理语种**」可自行增删语言类别：

- **新增**：填语言代码（如 `tr`，是 Excel 的列头，全局唯一）、中文名（土耳其语）、英文名（Turkish，可留空，用于自动识别 `lang_Turkish.ts` 之类的文件名），点「添加」后立即多出一列，翻译页与 TS 页的语言下拉也会同步更新。
- **删除**：点行内「删除」→「确认删除」两步确认。⚠️ 删除语种会**同时清除术语库里该语种的所有译文**（不可恢复）；最后一个语种不允许删除。
- **补齐内置语种**：误删了内置语种（如 `zh`、`en`）时，点这个按钮即可按内置顺序补回，不会影响自定义语种与已有数据。
- **列表分页**：语种列表同样每页 10 条（与其余列表同一套分页组件），新增语种后会自动跳到最后一页。
- 语种类别保存在本机浏览器，换台电脑需重新设置。

内置 13 个语种：`zh`（中文）、`en`（英语）、`ru`（俄语）、`es`（西班牙语）、`pt`（葡萄牙语）、`fr`（法语）、`de`（德语）、`ja`（日语）、`ar`（阿拉伯语）、`vi`（越南语）、`ko`（韩语）、`it`（意大利语）、`th`（泰语）。

### 列表操作

- **搜索与分页**：搜索同时对术语与所有译文模糊匹配；列表**统一每页 10 条**，底部分页条给出「共 N 条 / 第 x / y 页」，支持**上一页 / 下一页**与**输入页码跳转**（输入越界页码会自动收敛到合法范围）。术语库词条表、导入记录、生成结果记录、特殊词条、正则规则、管理语种、翻译页命中统计**各列表用的是同一套分页组件**，样式与交互完全一致。
- **表头全选**：勾选表头复选框即选中**符合当前筛选条件的全部数据**（含未显示页），翻页后选中状态保留；取消 = 筛选结果整体取消。
- **单个编辑**：点击行内「编辑」修改术语与各语言译文；术语（必填）全库唯一。
- **批量删除**：勾选行首复选框，点「删除选中（n）」一次性删除多条。
- **固定列**：语言列较多需横向滚动时，左侧「勾选 + 术语」列与右侧「大小写规整 + 操作」两列会**固定跟随**，不用拖滚动条就能看到并点击按钮。
- **调整列宽**：把鼠标移到表头单元格的**右边缘**，光标变成左右箭头后**按住拖动**即可加宽 / 收窄该列；拖动时相邻列同步反向变化，总宽保持不变。列宽自动记忆，点「重置列宽」恢复默认。语言列默认 140px。

### Excel 导入导出

- **导出**：列头 = `Term` + **当前全部语种** + `Casefix`。**这份文件本身就是模板** —— 删掉数据行只留首行即为一张空白术语表；术语库为空时导出，会自动附一行示例，文件名 `glossary_template.xlsx`。
- **导入**：**全量覆盖** —— 先清空当前列表，再按表格逐行重建；不做去重、不合并、不保留。导入前会弹**覆盖确认框**，写明清空条数、有效数据行数、未识别列头等警告。

### 一键翻译

工具栏的「一键翻译」把**词条原文**批量翻成指定语种的译文，省去逐条手工填写。

- **弹窗**：先选「源语言」（词条原文的语言），再在下方勾选目标语种 —— **默认全部不勾选**，可点「全选」；每个语种右侧标注「待 n / 总数」，显示该语种下还没有译文的词条数。弹窗顶部固定展示**翻译范围与规则**。
- **范围与规则**：只翻译**尚未有译文**的词条，某词条在该语种已有译文时**自动跳过、不覆盖**；翻译对象是词条的**原文（术语列）**，逐条单独送接口，**不套用**规则库的保护 / 替换规则；请求按「配置 → 请求间隔」节流并顺序执行，中途可「停止」，已完成的译文保留。
- **后台运行**：点「开始翻译」后**弹窗立即关闭，任务在后台异步执行**，可以继续做别的事（切换标签页、编辑术语、做 TS 翻译都不会中断）。进度**只由页面右下角的全局悬浮进度条呈现**（任何标签页都可见），实时给出**已完成 / 总数、百分比、当前词条**，并提供「停止」「查看详情」；点「×」只是收起，任务照常运行，结束时悬浮条会重新出现给出完成汇总。
- **结果**：完成后弹出**状态提示**（成功 / 返回空 / 失败条数，或已停止 / 连续失败已自动停止），悬浮条切换为完成态并给出汇总，可点「查看详情」看失败明细（最多 20 条）。译文在过程中**每 20 条落一次盘**（任务结束 / 停止时强制落盘）。任务运行期间关闭或刷新页面，浏览器会给出**离页确认提示**。本操作计入顶部统计（翻译次数 +1，字符数按实际送出的原文累加）。
- **并发保护**：同一时间只允许一个后台任务，运行期间「一键翻译」按钮禁用；连续 3 条全部失败会自动停止（通常是凭据或网络问题）。

### 大小写规整（按词条设置）

这个设置是**逐条**的，不是全局开关 —— 每个词条行都有一个「**大小写规整**」列（位于操作列左侧，与操作列同为右侧固定列），列内是「规整 / 不规整」开关（与规则库的「启用 / 停用」同款，点一下即切换）；「编辑词条」弹窗里也有同一个控件。它决定**该词条的译文片段**是否接受规则库「大小写规则」的规整。

- **规整**（默认）＝该词条译文随整段一起被规整（如「翻译结果全部转为小写」时 `PTO` → `pto`）。
- **不规整**＝该词条译文**保持术语库译文原样** —— 专有名词、缩写、大小写敏感的品牌名不会被改掉，接口译文的其余部分照常规整；同一段里可以同时存在两种词条。
- 设置随词条保存在本机；Excel 导入导出的 `Casefix` 列与之对应（`1`＝规整、`0`＝不规整，留空＝不改动原有设置）。对「翻译」页与 TS 翻译同时生效，改动只影响之后的翻译，不会回改已有译文。

### 术语库导入记录

术语库页面下方的「术语库导入记录」表记录**每一次「导入 XLSX」的结果**，列为：

**序号 / 文件名 / 导入时间 / 新增 / 删除 / 更新 / 跳过 / 操作**（固定 8 列，无「失败」列）。

- **计数口径**：本次导入是把「导入前的术语库」与「表格里的数据」按 `Term` 列**逐条比对**得到的四类结果。
  - **新增**：表格里有、术语库里没有 → 新增词条。
  - **删除**：术语库里有、表格里没有 → 该词条在导入后被移除（因为导入是全量覆盖）。
  - **更新**：`Term` 一致，但**译文内容有变化**（任一语种译文不同，或「大小写规整」开关不同）。
  - **跳过**：`Term` 与全部译文都无变化 → 内容一致，无需改动。
  - 另有**解析失败的行数**与**空行数**：空行直接忽略；解析出错的行计为失败、其余行不受影响。这两项数据仍保留在记录里，由「明细」弹窗与明细导出承载（列表列已按需求移除「失败」列）。
- **搜索文件名**：左上角搜索框按**文件名**模糊匹配（不分大小写），搜索只影响列表显示、并自动回到第 1 页；导入完成后会**自动清空搜索**，保证刚导入的那一条记录立刻可见。
- **明细**：点行内「明细」查看该次导入的**逐条比对结果**，并可导出 XLSX —— 导出文件含**两张工作表**：「**结果汇总**」（本次导入的统计，项目 / 内容两列，与记录列表字段一致）与「**详细记录**」（逐条比对明细：结果 / `Term` / 变更说明）。
- **下载**：点行内「下载」，拿到的是**该次导入上传的那份原始 XLSX 文件本身**（文件名与记录里的「文件名」一致），不是统计表。原文件未留存（超出本机留存上限）时会明确提示重新导入。
- **留存与上限**：每条记录会把原始文件留存在本机（转 base64）；**单条 ≤ 512 KB、全部记录合计 ≤ 2 MB**，超出上限时最旧的记录只保留统计。记录**最多保留最近 300 条**，按时间倒序、每页 10 条。

### 其它

- 首次打开会内置 **4 条示例词条**（拖拉机 / 地块 / 农场 / 客户），**译文覆盖全部 13 个内置语种**（`zh,en,ru,es,pt,fr,de,ja,ar,vi,ko,it,th`），可直接修改或删除。
- **下载提示**：导出 XLSX 时若浏览器未弹出保存窗口（常见于应用内置预览窗口），会自动弹出兜底窗口，可点「复制内容」把表格数据粘进 Excel（制表符分隔，可还原成表格）。
- 建议定期「导出 XLSX」备份（浏览器清除站点数据会丢失全部数据）。

## 六、规则库

规则库解决机器翻译最容易搞坏的两类内容：**不该翻的**与**必须照指定来翻的**。规则对所有页签生效（文本翻译、TS 翻译）。

### 特殊词条（强制替换）

把某个原文片段**强制指定为固定译文**。典型场景是字体名 —— 中文界面里写「方正兰亭黑简体」，到了目标语言机器上因缺字体容易显示异常，统一指定为 `Arial` 即可。

- 命中后该片段**不会被送进翻译接口**，最终译文里直接出现你指定的结果，因此不会被机翻改写。
- **指定译文留空**表示「保持原文」，即只保护不替换。
- 可设置**忽略大小写**（忽略的是原文片段的大小写，如词条 `PTO` 也能命中 `pto`）、可**停用**而不删除。
- **启用 / 忽略大小写都支持单个与批量切换**：点击行内的「启用 / 停用」「忽略大小写 / 区分大小写」按钮即单个切换；勾选多行后用工具条「启用选中 / 停用选中」「忽略大小写 / 区分大小写」按钮批量设置。
- 支持工具条按钮添加、行内编辑 / 删除、勾选批量删除、搜索，以及 **Excel 导入导出**（列头 `Src,Dst,Ci,Enabled`）。导入为**全量覆盖**（先清空后重建），导入前弹确认框。
- **分页**：特殊词条与正则规则两张表**统一每页 10 条**，与其余列表共用**同一套分页组件** —— 「共 N 条 / 第 x / y 页 + 上一页 + 页码跳转 + 下一页」；搜索后自动回到第 1 页，删除条目导致总页数变少时会自动收敛到最后一页。
- 与术语库的区别：术语库是「按语言给出各语言对照」，特殊词条是「无论什么语言都强制成同一个值」。

### 正则规则（不翻译的片段）

用正则匹配需要在翻译中**原样保留**的内容：命中的内容原样拼回译文、不送进接口，其余部分照常翻译。适用于 `<b>` 等富文本标签、`%1s` / `{0}` / `${VAR}` 等占位符、日期、邮箱、URL、UUID、单位符号等。

- **空格规整（启用 / 停用）**：表格里每条规则都有自己的「**空格规整**」开关，点行内按钮即可切换。启用后该规则命中的片段与相邻文字之间会被规整为**恰好一个空格**，且按位置分三种情形 —— **句中**前后各加一个空格（`已添加%1s台机具` → `已添加 %1s 台机具`）、**句首**仅后加一个空格、**句尾**仅前加一个空格（不会在行尾多留空格）。可有效防止接口把 `%1s` 翻成 `% 1s`。
- **一律区分大小写**：正则规则**不提供「忽略大小写」配置**，表达式按原样匹配；需要兼容大小写差异时，可依赖「大小写规则生效时的归一化双轮匹配」，或直接在表达式里写字符类（如 `[Aa]`）。旧版本导出的、含 `ci` 列的文件仍可导入，该列会被忽略。
- **启用支持单个与批量切换**：点击行内「启用 / 停用」按钮即单个切换；勾选多行后用工具条「启用选中 / 停用选中」批量设置。
- 支持 **Excel 导入导出**（列头 `Name,Pattern,Spacing,Enabled`），导入为**全量覆盖**（先清空后重建，导入前弹确认框）。
- 误删或想恢复内置规则时，点「恢复默认规则」即可回到出厂配置（**特殊词条不受影响**，替换前会备份当前这套规则）。
- 正则写错时表格会红字提示，导入时语法错误的行会自动跳过，不会影响已有规则。
- **重复表达式会被拦下**：新增 / 编辑时若表达式与已有规则完全相同，会提示「该正则表达式已存在」并放弃保存（编辑自己不算重复）。

### 规则测试

页面下方有**规则测试**输入框：粘贴一条真实的 `.ts` 原文，实时看到切分结果 ——

- 虚线框 = **待翻译片段**（送进翻译接口）
- 绿色系 = **保护片段**（原样保留）：与翻译页「正则规则」**用同一个类**，所以同样**按规则分色阶**（不同规则不同底色与线型，悬浮可看规则名）
- 橙色 = **特殊词条**（替换为指定译文）：与翻译页「规则库特殊词条」**用同一个类**

这三类的底色 / 边框 / 圆角 / 内边距不是「看起来像」，而是与翻译页**共用同一批 class 与同一套样式令牌**，改一处两处同步，不会漂移。图例中的色卡用的也是这两个类本身。

**图例与翻译页用的是同一个组件、同一套说法**（同一个 `.hl-legend` 结构：色卡 + 说明 + 右侧优先级提示，字号 / 间距 / 上方分隔线全部同源），只有条目不同：规则测试只跑「规则库」，不涉及术语库，所以不出现「术语库词条」那一项。图例由左到右即命中优先级（**规则库特殊词条 > 正则规则 > 待翻译片段**）。

底部会统计「共 N 个片段，其中 M 个需要送进翻译接口」，可在正式翻译前先验证规则是否写对。

### 大小写规则（翻译结果）

规则库最下方一卡，控制**翻译结果的大小写**，只作用于送接口翻译后返回的片段（保护片段、占位符、规则库特殊词条的替换结果不受影响；**术语库词条片段**是否被一并规整，由该词条在术语库里的「规整 / 不规整」设置决定）：

- **翻译结果全部转为小写**：默认开启，关闭则保留接口返回的原始大小写。
- **句子首单词首字母大写**：开启后，每个句子（按 `. ! ? …` 等标点切分）的首字母大写。
- **名词单词除介词外每个单词首字母大写**：开启后按「标题式」处理 —— **仅当整个片段被判定为名词**（不含 `. ! ? ;` 等句末标点、不含动词 / 人称代词（`is` / `are` / `he` / `they` 等），且不超过 12 个单词）时生效；介词、冠词、连词（`of` / `the` / `de` / `und` 等，多语言内置词表）保持小写，其余单词首字母大写；`GPS`、`ISO` 这类全大写缩写原样保留。

两条首字母大写规则**各自可独立开关**，均对**所有目标语言**生效。规则按「先小写 → 句子首字母 → 标题式」的顺序叠加。卡片内提供**规则测试**：输入文本即可实时看到处理结果。

翻译页会把大小写规则**实际改动的字符**用蓝色虚线高亮标出（悬浮提示标明是哪几条规则在起作用），但按设计**不纳入命中统计**。同时，大小写规则生效时术语与特殊词条的匹配会忽略大小写差异，保证统计结果不因大小写写法而波动。

### 内置默认规则

首次打开时规则库已预置 **1 条特殊词条 + 13 条正则规则**，可自由增删改：

| # | 规则名称 | 处理方式 | 空格规整 | 说明 |
| --- | --- | --- | --- | --- |
| — | 特殊词条：方正兰亭黑简体 → `Arial` | 强制替换 | — | 字体名统一替换，避免目标语言机器缺字体 |

| 3 | 占位符 - 百分号格式化占位符 | 保护 | **是** | `%1`、`%1s`、`%L1`、`%s`、`%d`、`%n`、`%.2f` 等原样保留 |

## 七、TS 翻译（Qt Linguist `.ts` 文件）

页面按**两个步骤**分成两个页签，按顺序做完即可；全程支持**一次处理多个文件**（多选或整个文件夹）：

- **步骤一（`.ts` → Excel）**：批量导入 `.ts` → 生成待翻译的 Excel。
- **步骤二（Excel → `.ts`）**：上传翻译完成的 Excel → 回写生成翻译后的 `.ts`。

两个步骤共用同一份数据：**步骤一的 `.ts` 列表就是步骤二的回填目标**，步骤二里不需要（也无法）再选一次 `.ts`（步骤二**只上传 Excel**，因为表格是通过「工作表名 ↔ `.ts` 文件名」配对的）。

- **同名 `.ts` 只保留一份**：重复导入同名文件时，会**用新导入的内容替换原条目**并给出提示。这样可避免同一文件被机器翻译两遍（重复扣接口额度、顶部「已翻译字符数」虚高），也避免生成两个同名文件后拿错。

### 翻译范围（哪些条目会被翻译）

Qt 用 `<translation type="…">` 标记条目状态。工具按状态决定**翻译范围**，而这个范围**可以自己配置** —— TS 翻译页顶部的「**翻译范围**」一行有四个开关，两个步骤共用：

- **勾选** = 该类条目**送进翻译接口**（即使里面已有译文，也会被本次译文覆盖重翻）；
- **不勾选** = **不送接口**，文件里原样保留，并在文件明细里标出跳过原因。

| `<translation>` 的状态 | 翻译范围里的开关 | 默认 | 勾选后 | 不勾选时 |
| --- | --- | --- | --- | --- |
| `type="unfinished"` | **未翻译** | **✓ 勾选** | 翻译并写入（里面已有草稿译文会被覆盖） | 未纳入翻译范围，原样保留 |
| `type="vanished"` | 已废弃 | 未勾选 | 翻译并写入 | 跳过并标注「已废弃」 |
| 无 `type`，且译文非空 | 已有译文 | 未勾选 | 重新翻译并**覆盖**已有译文 | 跳过并标注「已有译文」（原样保留、不改动） |
| 无 `type`，且译文为空 | 空白无标记 | 未勾选 | 翻译并写入 | 跳过并标注「空白无标记」 |

- **默认只翻译 `unfinished`（未翻译）**：其余三类都不动，文件保持原样；点右侧「**恢复默认**」可随时回到这个口径。
- 配置对**两个步骤**同时生效，并记在本机（下次打开仍是上次选的范围）。
- ⚠️ 勾选「**已有译文**」会**覆盖**已经人工完成的译文，改动前请先确认。
- 文件列表里的**待翻译条数**＝**当前翻译范围内**（即勾选类型）的条目总数；数字下面的说明**按类型逐类列出**（未翻译 / 已废弃 / 已有译文 / 空白无标记），与「翻译范围」一栏的四个开关**一一对应**，**合计恒等于这个数字**。未勾选类型的条目**不计入本列**；把鼠标停在该数字上可看处理结果细分（待机翻 / 已机翻 / 原样保留 / 留空 / 失败）与范围外条数。

### 步骤一：导入 `.ts` → 生成 Excel

1. 选择**源语言**；点「多个文件」按 Ctrl **多选 `.ts`**，或点「选择文件夹」（自动导入文件夹内全部 `.ts`）。可点「载入示例 .ts」先试跑。
2. 目标语言从文件名自动识别（如 `lang_English.ts` → 英语、`lang_Russian.ts` → 俄语、`lang_Turkish.ts` → 土耳其语；识别失败可在列表中手动指定）。
3. 文件列表六列：**文件名 / Context 数 / 条目数 / 待翻译 / 目标语言 / 操作**。
4. 点「**生成 Excel（自动机翻 + 术语/规则处理）**」：已配置接口时先自动机翻全部待翻译条目（按配置页的**接口请求间隔**节流，相同原文只请求一次），再产出 Excel 供人工校对；**未配置接口时只做术语与规则的离线预翻译**，可直接在 Excel 中人工翻译。机翻期间进度显示在**页面右下角的悬浮进度条**上。
5. **每个 `.ts` 各自生成一个独立的 Excel**，文件名＝**原 `.ts` 文件名（去扩展名）+ `_` + 14 位时间戳 + `.xlsx`**，例如 `lang_English.ts` → `lang_English_20261008153045.xlsx`（同一次生成的多个文件共用一个时间戳）。未设「默认下载路径」时多个文件**打包成一个 `.zip`**。
6. 生成的 Excel **行数恒等于该 `.ts` 的条目数**（全部状态都在，逐条可对照），列固定为 `Source / Translate / Target / Type / NeedTranslate / Key`。

**列表里三项指标的含义与统计口径**

| 列 | 含义 | 统计口径 |
| --- | --- | --- |
| **Context 数** | 该 `.ts` 里 `<context>` 节点的个数（Qt 用来分组的「语境」块） | 描述**文件本身**，与「翻译范围」的勾选无关；空的 `<context>` 也计入 |
| **条目数** | 该 `.ts` 解析出的 `<message>` 条目总数 | **含全部状态**（未翻译 / 已废弃 / 已有译文 / 空白无标记一律计入），与文件里实际的 `<message>` 数量一致 |
| **待翻译** | **当前翻译范围内**（勾选类型）、本次真正要处理的条目总数 | ＝各勾选类型条数之和；数字下面的说明按类型逐类列出，**各类之和恒等于这个数字**；未勾选类型的条目不计入本列 |

> Context 数与条目数描述的是**文件本身**，改「翻译范围」不会变；待翻译描述的是**本次任务**，会随页签顶部「翻译范围」的勾选实时变化。

### 步骤二：上传翻译后的 Excel → 生成翻译后 `.ts`

- 可**多选 Excel** 或**选择文件夹**（自动读取其中的全部 Excel）。
- 本步的列表**来自上传的 Excel**（不照搬步骤一的 `.ts` 列表），**一个工作表一行**，六列依次是：**文件名 / 工作表 / 数据行 / 翻译行数 / 不翻译行数 / 操作**。
- **文件名**＝该工作表所在的 Excel 文件（输出 `.ts` 与它同名）；**数据行**＝该工作表里的数据行数（不含表头，空行已忽略）；**翻译行数 / 不翻译行数**＝这张表里**会被写回 / 不会被写回**的行数，按 `NeedTranslate` 列判定（`true` 计入翻译行数，其余计入不翻译行数），两者之和恒等于数据行数。
- **回填只认 `NeedTranslate` 列**：只有该列为 `true` 的行才会被写回 `.ts`（`false` / 空白 / 认不出的值一律跳过，`.ts` 原样保留）。上传的表格**没有**这一列（升级前生成的旧表格、手工拼的模板）时，回落到按当前「翻译范围」判断，范围为外的行不写回。
- **输出 `.ts` 与对应 Excel 表格同名**：`lang_English_20261008153045.xlsx` → `lang_English_20261008153045.ts`（去掉 Excel 文件名的扩展名换成 `.ts`）。若在 Excel 里改过文件名，输出就跟着改；工作表名仍必须与 `.ts` 文件名对应（工作表名决定「这张表回填哪个 `.ts`」）。
- **表头识别**：列头大小写不敏感（`source` / `Source` 都能读）；有 `NeedTranslate` 列时按它判定「翻译 / 不翻译」，**没有**这一列时列表里的「翻译行数」回落为 `Target` 列有内容的行数；表格完全没有表头时按列序 A / B / C 读取。
- 工作表名与步骤一导入的 `.ts` 文件**一一对应**：对不上的工作表**不会生成**，会在**校验警告**里提示（请回到步骤一导入同名 `.ts` 后重试）。点该行的「移除」可以只删掉这个工作表（不影响步骤一的 `.ts` 列表）。
- 读取时会校验：条目是否缺失、是否存在未知 `Key`、`Source` 列是否与 `.ts` 原文一致、`NeedTranslate` 是否有空值，发现异常会在页面顶部给出**校验警告**。
- 勾选「Target 有内容时移除 unfinished 标记」可把已翻译条目标记为完成（默认勾选）。
- 点「生成翻译后 .ts 文件」后逐文件回填并交付，进度同样显示在**右下角悬浮进度条**上（单位「个文件」），中途也可「停止」。汇总里会分别列出**写入条数**、**跳过未修改**与**跳过未勾选翻译的行数**。
- **多个文件会自动打包成一个 `.zip`**（文件名带文件个数与时间戳）：浏览器对「一次用户操作触发多个下载」有拦截策略，逐个下载只会保存第一个，打包成一个文件才不会有文件被静默丢掉。单个文件仍按原名直接下载，不打包。
- 若本步骤设了「**默认下载路径**」，则不打包，生成的文件会**直接逐个写进所选文件夹**。

### 生成结果记录（两个步骤各一张表）

两个步骤页签底部各有一张**「生成结果记录」**表，样式与交互**完全照搬「术语库导入记录」** —— 同一套表格样式、同一套分页组件，同样支持按文件名搜索与单条操作：

- **记录时机**：步骤一每次「生成 Excel」、步骤二每次「生成翻译后 .ts 文件」都会新增一条记录（中途手动停止同样记录已生成的部分）；最多保留最近 300 条，按时间倒序、每页 10 条。步骤一的表只显示步骤一的记录，步骤二同理。
- **列口径（固定 7 列）**：**序号 / 结果文件 / 生成时间 / 成功 / 失败 / 跳过 / 操作**。非 0 的数字加粗显示。
- **三态口径严格统一，两个步骤一致**：
  - **成功** ＝ **翻译成功的条目数**（步骤一＝写进各表的数据行数中，属于翻译范围且翻译成功的条数；步骤二＝成功写回 `.ts` 的译文条数）；
  - **失败** ＝ **翻译失败的条目数**（步骤二为**行级**统计，含整文件生成失败的行；步骤一通常为 0），点操作栏「明细」定位；
  - **跳过** ＝ **不在翻译范围内的条目数**（`NeedTranslate` 不为 `true`、译文与 `.ts` 已有内容一致无需改动等）。
  - 记录里保存的「翻译行数」＝本次涉及的翻译范围内条目数，**成功 ＋ 失败 ＋ 跳过 恒等于全部条目数**。
- **搜索**：按**结果文件名**模糊匹配（不分大小写），搜索只影响列表显示、并自动回到第 1 页；生成完成后会**自动清空搜索**，保证刚生成的那条记录立刻可见。
- **明细**：点行内「明细」打开该次生成的**结果明细**（统计表给出成功 / 失败 / 跳过，明细表逐条列出失败条目与原因），**失败为 0 时同样可以打开**（显示「没有失败条目」空态，按钮不置灰）；导出 XLSX 含**两张工作表**：「**结果汇总**」（本次三态统计，与列表三列同源）与「**详细记录**」（序号 / 文件 / 工作表 / `Key` / 原文 / 失败原因 / `source` 是否不一致）。弹窗结构与「术语库导入记录」的明细完全一致。
- **下载**：点行内「下载」，拿到的就是**这一次生成的结果文件本身** —— 步骤一是本次的 **Excel（`.xlsx`）**（一次生成多个时是打包的 `.zip`）、步骤二是本次的 **`.ts`**（多个文件时为 `.zip`），与生成时是**同一份内容、同一个文件名**；该步骤设了「默认下载路径」时同样直接写进该目录，并自动打开所在文件夹。按钮的悬浮提示会写明该条记录的文件类型与大小。
- **原文件留存在本机**：每条记录都会把结果文件原样留下（步骤一 Excel 转 base64、步骤二 `.ts` 存文本），所以**不必在生成时抢时间保存**。受浏览器本机存储限制有两条上限：**单条 ≤ 512 KB、全部记录合计 ≤ 2 MB**；超出上限时**最旧的记录只保留统计**（该条行内「下载」会提示已不在本机留存，重新生成一次即可）。统计与文件名不受影响，最多仍是 300 条。

### 默认下载路径（步骤一 / 步骤二各自独立）

两个步骤卡片里各有一行「**默认下载路径**」，可以分别为它们指定保存文件夹，**互不影响、各自记住**：

- 点「**选择文件夹**」在系统目录选择框里授权一个目录；授权成功后该行**显示所选文件夹名**（「已设置：文件夹名」），并在右侧出现「**清除**」按钮。
- 界面只显示**文件夹名**：浏览器出于安全限制不向页面提供所选目录的完整路径；本机还额外记了一份目录名（`ztw_dlpath_names`），重开页面（或本机存储被清理）时即使授权已失效，该行也会显示「上次设置：文件夹名 · 需重新选择以授权」，而不是退回「未设置」。
- 设置后，**该步骤生成的文件直接写进这个文件夹**，不再弹浏览器的保存窗口：步骤一产出的 Excel、步骤二产出的 `.ts`（多文件不再打包 `.zip`，逐个写入）、以及该步骤「生成结果记录」里单条下载的结果文件都会落在这个目录。
- 授权只保存在**本机浏览器**（目录句柄存在 IndexedDB 的 `ztw_fs` / `dirs`）；换电脑、换浏览器或清除站点数据后需要重新选择。
- 浏览器要求**重新授权**时会在你点「生成」的那一刻自动请求一次；若**未授权 / 写入失败 / 浏览器不支持**，会**自动回落到浏览器下载**并在提示里说明，不会静默丢文件。
- 该能力依赖浏览器的 File System Access 接口：**Chrome / Edge 等 Chromium 内核浏览器**可用；不支持的浏览器该行显示「当前浏览器不支持 · 文件走浏览器下载」且按钮置灰。

### 翻译进度与停止（右下角悬浮进度条）

TS 翻译的**两个步骤**都与术语库「一键翻译」共用**同一条右下角悬浮进度条**，全站只有这一处进度显示：

| 步骤 | 进度条标题 | 计数单位 | 触发时机 |
| --- | --- | --- | --- |
| 步骤一：机翻 | TS 翻译 | 条 | 点「生成 Excel」且已配置接口时 |
| 步骤二：回填生成 | TS 翻译 | 个文件 | 点「生成翻译后 .ts 文件」时 |

- 进度条实时显示：**已完成 x / y、百分比、成功 / 失败条数、当前正在处理的文件与条目**。任务完成后的汇总里也会带上处理过的文件名（单个文件直接写文件名，多个文件写总数）。
- **「停止」**：点了立即停下（当前这一条做完后不再继续），**已完成的译文保留**；步骤一停止后仍会照常生成 Excel（未翻的条目保持未翻译），步骤二停止后已生成的文件照常交付。
- **任务期间**步骤一的「生成 Excel」与步骤二的「生成翻译后 .ts 文件」都会禁用，避免重复发起；任务结束后自动恢复。
- 完成后进度条切换为**完成态**并给出汇总，可点「查看详情」看失败明细（最多 20 条）；标题栏的 **×** 分两种情形：**运行中**＝收起进度条（任务照常在后台运行），**已结束**（完成 / 停止 / 中断）＝关闭这条进度。
- 进度条是**页面级**的：切到别的标签页也会一直显示，不影响任务继续。

## 八、Excel 结构说明

**行数恒等于源 `.ts` 的条目数**：`.ts` 里有多少个 `<message>`，表格里就有多少行 —— 不论它属于哪一类、也不论「翻译范围」勾了什么。所以拿起表格就能和原文件逐条对照。

**表头一律大驼峰（首字母大写）**，顺序固定、不要改名：

| 列 | 含义 |
| --- | --- |
| `Source` | 原文（条目的 `<source>`） |
| `Translate` | `.ts` 里已有的译文 |
| `Target` | **翻译后的内容，就是最终要写回 `.ts` 的值**（人工只改这一列） |
| `Type` | 该条目的类别（只作标注，不参与回填） |
| `NeedTranslate` | 该行在由本表格生成 `.ts` 时**是否需要翻译**（`true` / `false`） |
| `Key` | 稳定标识，排序 / 删行后仍能对回原条目，**请勿删除** |

`Type` 列取值与 `.ts` 里的状态一一对应，就是「翻译范围」里的那四类：

| `Type` | 对应 `.ts` 状态 | `Target` 列 | `NeedTranslate` 默认值 |
| --- | --- | --- | --- |
| 未翻译 | `<translation type="unfinished">` | 勾选了「未翻译」＝机翻 / 离线预翻译结果；未勾选＝留空 | 勾选＝`true`，未勾选＝`false` |
| 已废弃 | `<translation type="vanished">` | **留空**（废弃译文不作为待回填内容） | `false` |
| 已有译文 | 无 `type` 且译文非空 | 照抄 `.ts` 里已有的译文（勾选该类别时改为重新翻译的结果） | 勾选＝`true`，未勾选＝`false` |
| 空白无标记 | 无 `type` 且译文为空 | 留空（勾选该类别时才会有内容） | 勾选＝`true`，未勾选＝`false` |

> `Type` 以**中文**写入，方便直接阅读；它只作标注，**不参与回填**（回填只看 `NeedTranslate` 与 `Target`）。

> `NeedTranslate` 的**默认值只在生成时写一次**：凡是「翻译范围」里勾选了的类别默认 `true`，其余默认 `false`。生成之后它就是**这张表自己的设置**，与页面上「翻译范围」的勾选再无关系 —— 想让某一行在本轮被写回，把它的 `NeedTranslate` 改成 `true`；想彻底跳过某一行，改成 `false`。只接受 `true` / `false`（也认 `1` / `0`、`是` / `否`、`yes` / `no`），**留空或写错一律按「不翻译」处理**并在校验警告里提示行数。

### Excel 编辑注意

- **只改 `Target` 列**（以及按需改 `NeedTranslate`），不要修改 `Source` / `Translate` / `Type` / `Key` 列的内容与顺序。
- 未纳入「翻译范围」的类别（默认是「未翻译」之外的三类）**同样会出现在表格里**，`Target` 列是 `.ts` 现状的照抄值、`NeedTranslate` 是 `false`，用于对照；把 `NeedTranslate` 改成 `true` 即可让它在回填时生效。
- 复数条目（`numerusform`）的多个形式用 `|` 分隔，如 `%n tractor | %n tractors`；不写 `|` 时各形式会填入同一译文。
- `NeedTranslate` 为 `true` 但 `Target` **留空的行不会被写入原文件**（保持原状，即仍是未翻译）。
- `.ts` 中原有的缩进、注释、`vanished` / `unfinished` 状态、`numerusform` 复数结构、`<!DOCTYPE TS>` 与 XML 声明全部保留，输出与原文件逐行差异极小。
- 步骤二需与步骤一在**同一浏览器会话**中完成（导入的文件结构保存在内存中）。

## 九、Excel 格式（术语库 / 规则库）

导入、导出统一为 **`.xlsx`**（Excel 2007 及以上），首行为列头。**列头一律大驼峰（首字母大写）**，如 `Source` / `Target` / `Enabled` / `Casefix`。**列的顺序可以随意调整**，导入时按列头名识别（**大小写不敏感**，`source` 与 `Source` 等价，旧文件照样读得回来）；不需要的列可整列删除，多余列会被忽略。

> 用 WPS / Excel 打开 `.xlsx` 直接编辑即可；只要**第一行保留列头**就不会解析错位。首行若缺少可识别的列头，会按「`Term` + 当前全部语种」的顺序猜测并给出提示。

### 术语库（术语库页）

列头：`Term` + **当前语种列表**（默认 `Zh,En,Ru,Es,Pt,Fr,De,Ja,Ar,Vi,Ko,It,Th`，即「管理语种」里的全部语言代码，可按需增删；语言代码列头也首字母大写，导入时大小写不敏感）。第一列为术语，其余为各语言译文，无需的列留空即可；最后一列 `Casefix` 是该词条的「大小写规则规整」开关（`1`＝规整、`0`＝不规整，留空＝不改动原有设置），不需要可整列删除。旧版本含 note / category 列的文件也能正常导入，多余列会被忽略。

| Term | Zh | En | Ru | Es |
| --- | --- | --- | --- | --- |
| 拖拉机 | 拖拉机 | Tractor | Трактор | Tractor |
| 地块 | 地块 | Land parcel | Участок земли | Parcela |

- 导入支持宽松列头别名：术语列可写 `Term` / `term` 或 `术语`；语种列可写**语种代码**（`En`、`Zh-Tw`、`zh-TW`）、**中文名**（`英语`、`俄语`）、**英文名 / 本地名**（`English`、`Русский`），也可带 `译文_` 前缀（`译文_en`、`译文_英语`）。**列头写中文名的表格（同事或旧模板发来的常见形态）同样能正确识别。**
- **导入为全量覆盖**：清空当前词条后按表格逐行重建，**不做去重合并**；空行跳过，解析出错的行计为失败（其余行不受影响）。导入前弹覆盖确认框。
- 导入的列头若既不是术语列、也不是任何已知语种（例如 `备注`），导入完成弹窗会**列出未识别的列名**并说明这些列未被导入；**一个语种列都没认出来时会红字警告**。
- 导入的列头若是语种代码、但不在当前语种列表中（例如别人发来的表里有 `tr` 列），译文会被保留，导入完成时会提示；到「管理语种」新增该代码后即可显示。
- 导入只读取工作簿的**第一个工作表**；若该工作簿含多个工作表，导入完成弹窗会明确说明「只读了第一张表」，请另存为单独文件后再导入其余表。

### 规则库 · 特殊词条（规则库页）

列头：`Src,Dst,Ci,Enabled` —— 特殊词条原文、指定译文、是否忽略大小写（`1`/`0`）、是否启用（`1`/`0`）。

| Src | Dst | Ci | Enabled |
| --- | --- | --- | --- |
| 方正兰亭黑简体 | Arial | 1 | 1 |

- `Dst` 留空表示命中后保持原文（不做替换）。
- **导入为全量覆盖**：清空当前列表后按表格逐行重建。导入前弹确认框。

### 规则库 · 正则规则（规则库页）

列头：`Name,Pattern,Spacing,Enabled` —— 规则名称、正则表达式、是否**空格规整**（句中前后各加一个空格、句首仅后加一个空格、句尾仅前加一个空格）、是否启用（均用 `1`/`0`）。旧版本文件里的 `mode` 与 `ci`（忽略大小写）两列会被忽略：正则规则统一按「保护片段」处理，且**一律区分大小写**。

| Name | Pattern | Spacing | Enabled |
| --- | --- | --- | --- |
| 占位符 - 大括号占位符 | `\{[^}]*\}` | 1 | 1 |
| 纯数字（整数、小数、负数） | `-?\d+(\.\d+)?` | 0 | 1 |
| 时间 / 日期格式 | `\d{4}[-/]\d{1,2}[-/]\d{1,2}` | 1 | 1 |

> 表达式里若含 `|`（如内置的「百分号格式化占位符」规则），写进单元格时用 `\|` 转义即可；完整清单见上一节「内置默认规则」。

- **导入为全量覆盖**：清空当前正则列表后按表格逐行重建；表达式为空或语法错误的行会自动跳过，不影响其他行。导入前弹确认框。
- **没有列头的旧文件也能读**：4 列按 `name,pattern,spacing,enabled` 识别，5 列（旧版多了 `ci`）按 `name,pattern,spacing,ci,enabled` 识别并忽略那一列。
- 误删或想恢复内置规则时，点「恢复默认规则」即可回到出厂配置（特殊词条不受影响）。

## 十、数据与隐私

- 所有数据（配置凭据、术语库、导入记录、TS 生成结果记录、语种类别、界面状态、翻译字符数用量）仅保存在**本机浏览器 `localStorage`** 中；「默认下载路径」的目录授权存在 **IndexedDB**。本工具不向任何服务器上传你的数据；仅翻译请求会发送到你配置的翻译接口。**本 `.html` 文件本身不含任何你的数据** —— 把它发给任何人，对方打开后都是全新空白的出厂状态（首次打开注入的示例词条也只在各自浏览器内生成，不随文件走）。
- 凭据在本机明文存放，请勿在公用电脑上保存密钥。
- 清除浏览器数据会丢失全部术语与配置，请养成定期导出 XLSX 备份的习惯。
- 更完整的数据存放位置、网络行为、备份与清理说明见 [04-数据与隐私](04-数据与隐私.md)。
