# 01 · 快速开始（5 分钟上手）

## 目标场景

你有一堆 Qt 的 `.ts` 翻译文件，要批量翻成英文（或其他语种），并且要保证术语统一、占位符不被翻坏。

## 两条路线：机器翻译 / 人工翻译

TS 翻译有**两条路线**，下面第 1～5 步的机械流程**完全一样**，区别只在 Excel 里 `Target` 列的译文**由谁产生**：**机器翻译**由翻译服务自动出初稿，**人工翻译**由译员逐条填写。两条路线**可以混用**（先机翻铺初稿，再由译员在同一份 Excel 上精修，最后统一回填）。

| 对比项 | 机器翻译（机翻） | 人工翻译 |
|---|---|---|
| 译文来源 | 翻译服务自动生成 | 翻译人员逐条填写 |
| 是否必须配置翻译服务 | **必须**（否则无法生成 Excel） | **必须**（未配置时步骤一整体拦截） |
| 速度 / 成本 | 快；按字符计费（各平台有免费额度） | 慢；按人工计费，取决于译员排期 |
| 质量 | 不稳定，**必须人工复核**（见下节） | 取决于译员与词表，通常更贴合语境 |
| 适用场景 | 条目多、语种多、工期紧 | 术语敏感、对外发布、法规 / 合同 / 界面文案；或没有可用的翻译服务 |

### 方式 A · 机器翻译：完整步骤

1. 到「配置」页选一家翻译服务、填好账号信息，点「**测试连接**」确认可用（第 1 步）。
2. （建议先做）配好**术语库**与**规则库**（第 2 步）—— 这两份数据直接决定机翻质量，事后补配要重翻。
3. 「TS 翻译」页步骤一：选源语言 → 导入 `.ts`（可多选文件 / 选文件夹）→ 勾选「翻译范围」（默认只勾「未翻译」）→ 点「**生成 Excel（自动机翻 + 术语/规则处理）**」（第 3 步）。
4. 等右下角进度卡跑完：**每个 `.ts` 各得到一份 Excel**，待翻条目的 `Target` 列已填好机翻译文。
5. **在 Excel 里逐行复核 `Target` 列**（只改这一列）：重点看含占位符 / 标签的行、术语库命中的行、长句与否定句（见下节）。
6. 「TS 翻译」页步骤二：上传复核后的 Excel → 点「**生成翻译后 .ts 文件**」→ 到「生成结果记录」按**成功 / 失败 / 跳过**对账（第 5 步）。

### 方式 B · 人工翻译：完整步骤

1. 「TS 翻译」页步骤一：选源语言 → 导入 `.ts` → 勾选「翻译范围」→ 点「生成 Excel」。
   - **未配置翻译服务时无法生成**——步骤一整体拦截，会提示先到「配置」页完成配置；
   - **已配服务但想全人工**时，机翻初稿只能当参考：要么让译员逐行改写 `Target`，要么把需要重译的行 `NeedTranslate` 保持 `1`、其余改成 `0`。
2. **提取翻译词条**：把生成的 Excel 交给翻译人员 / 翻译公司；同时把**术语库「导出 XLSX」**一并交付 —— 机翻与人工用的是同一份词表，术语口径才统一。
3. **约定填写规则**：译员**只填 / 只改 `Target` 列**，`Source` / `Translate` / `Type` / `Key` 一律不动，不删列、不重排行（`Key` 是回填时对回原条目的依据，缺了该行会被整行跳过）。
4. **译员回传**：保持表头与行序不变的**同一个 Excel**。
5. **步骤二 · 写回**：上传译员回传的 Excel → 点「**生成翻译后 .ts 文件**」。**回填只认 `NeedTranslate` 列**：只有该列为 `1` 的行才会写回，译员新填了译文的行记得把这一列改成 `1`（不写回时 `.ts` 保持原样）。
6. **对账**：在「生成结果记录」确认成功 / 失败 / 跳过；有失败条目点「明细」定位到文件名与原因。

> 两条路线的**产物、命名、记录口径完全一致**（见第 3、5 步）：都只认 `Target` 与 `NeedTranslate` 两列，回填都遵循「条目级保真」——只有被改动过的条目才会被替换，未改动的条目在 `.ts` 里保持原样（含缩进与转义）。

## 第 0 步：把程序跑起来

双击 **`src/ts-translate.html`**，用 Chrome / Edge / Firefox 打开即可；也可放到内网静态服务器共享，见 [README 第二节](../README.md#二快速开始)。

页头有七个页签：**配置 / 翻译 / 术语库 / 规则库 / TS 翻译 / Excel 翻译 / 使用说明**。日常只用「配置」与两个翻译页。

> **翻什么用哪页**：翻**一段文字**用「翻译」页；翻**一整张 Excel 表格**（按列头语种代码逐格翻、只翻空白格）用「**Excel 翻译**」页；翻 **Qt 语言文件 `.ts`** 用「**TS 翻译**」页。后两者都会用到「配置」页的翻译服务，也都受术语库与规则库约束。

> 没有密钥也能用：把 Excel 里翻好的 `Target` 填回来，工具只做术语与规则校正 + 回写，不走机翻。

## 第 1 步：配置翻译引擎（配置页）

只需要填一次，之后一直保存在本机浏览器里。**五家服务任选其一**：

| 服务 | 需要填什么 | 备注 |
|---|---|---|
| **阿里云翻译**（默认，推荐） | `AccessKey ID` / `AccessKey Secret` | 可直连，无需代理；浏览器端完成 TC3-HMAC-SHA256 签名 |
| 腾讯云翻译 | `SecretId` / `SecretKey` / 地域 `Region` | 浏览器端完成 HMAC-SHA1 签名；**必须配代理地址前缀** |
| 百度翻译开放平台 | `APP ID` / `密钥` + 服务地址 | 标准版请求间隔填 1000；**必须配代理地址前缀** |
| 有道智云翻译 | `应用ID(appKey)` / `密钥(appSecret)` + 服务地址 | **必须配代理地址前缀** |
| AI 大模型翻译 | `API Key` / 模型名称 / 服务地址 | OpenAI 兼容；可直连，支持 OpenAI / DeepSeek / 通义千问 等 |

- 页面上会按所选服务**动态显示对应字段**；「代理地址前缀」只对必须走代理的三家显示。
- **翻译慢可开并发**：配置页「**翻译线程数**」填 `2～8` 会同时发出多条请求、速度约成倍提升（默认 `1`＝逐条串行）；并发过高若提示「请求频率超限」，把线程数调小或把请求间隔调大，百度标准版建议保持 `1`。请求间隔按**每条线程各自**计算。
- 填完点「**测试连接**」，通过再继续。失败时会给诊断结论（哪一项没配对、是不是被浏览器跨域拦下）。
- 配置页顶部还有「**剩余免费额度**」：按实际送进接口的字符数在本机扣减，总额度可改，每月自动清零。
- **顺手开好备份（建议）**：配置页最下方「**备份与恢复**」→「选择备份文件夹」（只登记目录，不生成备份）。以后想留档时点一下「立即备份」，就会把配置页 / 术语库 / 规则库 / 两个翻译页的数据存成该文件夹里的一个 JSON 文件（详见 [02-功能说明](02-功能说明.md#十二备份与恢复配置页)）；换电脑或清理缓存时「导入备份」即可整体复原。

## 第 2 步：准备术语库与规则库（可选，但强烈建议）

- **术语库**：`Term` + 各语种译文 + `Casefix`（该词条是否做大小写规整）。例如 `拖拉机 → Tractor`。
  首次打开内置 4 条示例词条（拖拉机 / 地块 / 农场 / 客户），译文覆盖全部 13 个内置语种，可直接改。
- **规则库**：分「特殊词条（强制替换）」与「正则规则（不翻译的片段）」两张表。
  **内置 5 条默认正则**，已覆盖 HTML 标签、大括号 / 百分号 / 方括号占位符、HTML 实体编码 —— 通常不需要自己再加。

两库都支持 XLSX 导入导出，一次整理长期复用。

> ⚠️ 两库的导入都是**全量覆盖**：先清空当前列表再按表格重建，不去重、不合并。导入前会弹确认框写明清空条数与警告。

## 第 3 步：步骤一 · 从 `.ts` 抽出待翻内容

TS 翻译页 → 步骤一：

1. 选择**源语言**，然后上传一个或多个 `.ts`（可多选文件，也可直接选文件夹）。
2. 在顶部「**翻译范围**」里勾选要处理的状态 —— 默认只勾 **未翻译 `unfinished`**（最常用）。
3. 点「**生成 Excel（自动机翻 + 术语/规则处理）**」。

结果：**每个 `.ts` 各生成一个 Excel**，文件名为 `原文件名_14位时间戳.xlsx`（同一次生成的多个文件共用一个时间戳；重名时在该文件名后追加 `-2`、`-3`，时间戳始终在末尾）；未设置默认下载路径时，多文件会自动打包成一个 `.zip`。

Excel 固定 6 列，**行数恒等于该 `.ts` 的条目总数**（不论它属于哪一类）：

| 列 | 说明 |
|---|---|
| `Source` | 原文（条目的 `<source>`） |
| `Translate` | `.ts` 里已有的译文 |
| `Target` | **翻译后的内容，最终写回 `.ts` 的就是它** —— 人工只改这一列 |
| `Type` | 条目的类别（中文标注，不参与回填） |
| `NeedTranslate` | 该行在由本表生成 `.ts` 时是否需要翻译（`1` / `0`） |
| `Key` | 稳定标识，排序 / 删行后仍能对回原条目，**请勿删除** |

## 第 4 步：校对译文

已配置接口时，步骤一已经自动机翻并写进 `Target` 列；人工只需要**在 Excel 里复核这一列**（复核要点见下节「机翻结果必须人工复核」）。

想手工控制某一行：把它的 `NeedTranslate` 改成 `1`（要写回）或 `0`（不写回）。

## 第 5 步：步骤二 · 回写生成新的 `.ts`

TS 翻译页 → 步骤二：

1. 上传第 4 步改好的 **Excel**（可多选 / 选文件夹）。步骤一导入过的 `.ts` 会自动带到这一步，不需要重复上传。
2. 表格会列出每个工作表：**文件名 / 工作表 / 数据行 / 翻译行数 / 不翻译行数 / 操作**，可先在页面上核对再生成。
3. 点「**生成翻译后 .ts 文件**」。

输出 `.ts` **按内容命名**，格式为 `工作表名_14位时间戳.ts`（如 `lang_English_20261010141530.ts`）—— 工作表名就是步骤一时的原 `.ts` 名，一个 Excel 里装多个工作表也能一眼区分；多文件同样打包成一个 `.zip`。

最后看下方的「**生成结果记录**」对账：

> **成功 + 失败 + 跳过 = 全部条目数**
> 「成功」＝翻译成功的条目数，「失败」＝翻译失败的条目数（点「明细」定位），「跳过」＝不在翻译范围内的条目数。

## 机翻结果必须人工复核

**机翻产出的是初稿，不是终稿 —— 回填 `.ts` 之前必须由人通读一遍。**

即便术语库与规则库都配好了，机翻仍可能出现这些问题：

- **错译 / 漏译**：一词多义、行业惯用语、否定与数量表达容易翻错；Qt 条目常是**没有主语的短句**（如「添加」「已保存」），引擎容易猜错主语或语气。
- **术语偏差**：术语库里**没有收录的词不会被替换**，同一个词在不同条目里可能被翻成两种写法。
- **占位符与标签风险**：`%1` / `%1s` / `{0}` / `<b>` 这类片段由规则保护、正常情况下不会被翻坏；但**规则被停用或改动**后仍可能被引擎破坏，尤其注意带参数顺序的 `%1 … %2`。
- **语序、大小写与标点**：目标语言的语序、句首大小写、全半角标点需要人眼确认。
- **脱离上下文**：条目是逐条独立处理的，看不到它在界面上的位置 —— 「这个按钮叫什么更合适」只有看界面才知道。

建议做法：

1. **先校准词表，再跑整批**：先在「翻译」页用几段典型文案验证术语与规则有没有生效（看结果区高亮与命中统计），再跑 `TS 翻译`。一次配好，后面所有文件都受益。
2. **优先核对三类高风险行**：① 含**占位符 / 标签**的行（确认未被破坏）；② **术语库命中**的行（确认替换正确、写法统一）；③ **长句、否定句与无主语短句**。
3. **善用 `Translate` 列做参照**：这一列是 `.ts` 里原有的译文（通常是历史人工译文），措辞往往比机翻更贴合产品；新旧不一致时**以人工译文为准**。
4. **只改 `Target` 列**：不要修改 `Source` / `Translate` / `Type` / `Key`，不要删列、不要重排行；`NeedTranslate` 按需改。
5. **抽查与全检结合**：条目多时先按第 2 条抽查高风险行，交付前再对关键界面（菜单、按钮、报错提示、参数说明）做一轮全检。
6. **拿不准就先不写回**：把该行 `NeedTranslate` 改成 `0`，它会保持 `.ts` 原样，等确认后再单独补翻。
7. **留档可追溯**：「生成结果记录 → 明细 → 导出 XLSX」会留存本次结果（成功 / 失败 / 跳过三态对账），便于回溯哪个文件、哪一条、结果如何。

> 一句话：**机翻负责铺量，人负责把关。** 工具把「抽词条 → 术语与规则校正 → 写回」这些机械环节做掉，并保证**未被改动的条目一字不动**；译文正确性最终由复核决定。

## 常见小问题

- **不知道翻了哪些**：步骤二列表给出每个工作表的「数据行 / 翻译行数 / 不翻译行数」，三者之和恒等于数据行数。
- **术语没生效**：先确认术语库里该词条是启用状态，再到翻译页看高亮预览。
- **占位符被翻坏**：在规则库里加保护规则（或确认它没被停用），重新生成。
- **`.ts` 没生成**：多半是工作表名与导入的 `.ts` 对不上，页面顶部的**校验警告**会说明。
- **换电脑**：最省事的是用配置页「**备份与恢复**」——在新机器打开本页 →「导入备份」即可整体复原；也可以术语库与规则库各自「导出 XLSX」，到新机器导入；**配置页没有导出**，密钥等只能靠「备份与恢复」留存（未配置备份文件夹时需在新环境重填）。
